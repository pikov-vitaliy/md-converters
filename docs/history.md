# История проекта md-converters

Хроника всех итераций (перенесено из CLAUDE.md 2026-08-29 при его
сокращении). Новые итерации дописываются СЮДА, нумерация сквозная.



1. Утилита `pdf2md` (PDF→MD) и `html2md` (HTML→MD) на MarkItDown.
2. `html2md`: маски `*`, папки, рекурсия `-r`, защита от перезаписи `-f`,
   front-matter, чистка, сводка, автоопределение кодировки cp1251.
3. Комплект (kit) + `install.ps1` + README + примеры; перенос на любой ПК.
4. Репозиторий на GitHub (private), лицензия MIT; `pdf2md` доведён до уровня
   `html2md`.
5. Слияние в универсальный `convert_to_md.py` (команда `tomd`), форматы
   Word/Excel/PowerPoint/CSV/URL и др., флаги `-o`/`--only`/`--keep-images`,
   пункт «Отправить → Конвертировать в Markdown», pip-пакет
   (`pyproject.toml`), CI (GitHub Actions). README с бейджами и англ.
   секцией.
6. v1.0.1: чистка артефактов PPTX — битые картинки-заглушки сворачиваются
   в плейсхолдер, управляющие символы (`\x0b` и др.) вычищаются; подавлен
   pydub-warning про ffmpeg; переход с `markitdown[all]` (0.0.2 на
   Python 3.14) на формат-экстры (0.1.6) в pyproject/install.ps1.
7. v1.0.2: фиксы по результатам аудита 2026-06-10
   (+ адверсариальное ревью самих фиксов): гарантированное закрытие fd в
   `_convert_reencoded`; развод одинаковых имён `(2), (3)...` теперь и
   без `-o`, со сверкой `source:` из front-matter лежащих на диске `.md`
   (повторный прогон части файлов попадает в «свои» цели), предсказание
   в интерактиве той же логикой; `-o`/`--only` без значения — явная
   ошибка и exit 2 (раньше молча игнорировались); `_suffix_set` срезает
   `*` с обеих сторон; data-URI-regex допускает парные `()` в SVG, но
   рвётся на первой непарной `)` — не съедает картинку-ссылку и соседнюю
   разметку; файл с `[` в имени берётся литерально, а не как glob;
   табы/CR в title нормализуются в YAML; подсказка при ImportError — без
   `[all]`; `markitdown` ограничен `<1.0.0`; classifiers и конфиг ruff в
   pyproject; CI: матрица 3.10/3.12/3.14 + windows-job + ruff + тесты
   пропуска, ошибок флагов (через `if`, не инертное `! cmd`) и регекспа
   data-URI; install.ps1 — гард PowerShell 7.2+ и fallback
   `pip install --user`; README синхронизирован (pwsh, экстры вместо
   `[all]`, развод имён).

9. **v1.2.0:** `--mirror`/`--preserve-tree` —
   зеркальная структура подпапок при выводе через `-o`; детектор PDF без
   текстового слоя (`pdf_text_layer` во front-matter + жёлтое
   предупреждение про сканы; с 2026-08-27 проверяется по pypdfium2-
   тексту самого PDF, чтобы не ловить ложное `absent` на русских PDF с
   плохим Markdown-извлечением; если PDFium видит полноценный текст, а
   MarkItDown — практически пустой результат, используется PDFium-текст)
   и распознавание image-only PDF. С 2026-08-27 также чинится
   систематическая карта шрифта из ведомственных PDF: cp1251-буквы
   `а…я` были записаны со сдвигом и извлекались как ASCII `0…O`
   (`о1еспеGении` → `обеспечении`). Детектор документный: нужен минимум
   смешанных слов и заметная доля дефектных символов, поэтому ГОСТы,
   версии и обычный латинский текст не затрагиваются;
   кастомная иконка пунктов контекстного меню и фиксы пункта Send To;
   56 pytest-тестов. 2026-06-16: репозиторий сделан публичным
   (Actions бесплатны), экшены CI переведены на Node 24 — см. заметку
   про CI выше.
10. **Извлечение PDF-таблиц через pdfplumber (2026-06-27).** По запросу
    пользователя (таблицы из PDF «сильно ехали»). Исследование +
    адверсариальная проверка кандидатов (pdfplumber выбран: MIT, локально,
    Python 3.14, без новых установленных зависимостей — уже тянется
    `markitdown[pdf]`; PyMuPDF отвергнут как AGPL, Docling/Marker/MinerU —
    torch/лицензии, LlamaParse — облако). Реализован вариант A+B: свой
    PDF-путь (`_pdf_tables_result` и сопутствующие) с фильтром таблиц,
    обрезкой/переэмитом прозы, отбросом пустых колонок, склейкой переносных
    таблиц, сборкой по порядку чтения; флаг `--pdf-tables auto|off`, поле
    `pdf_tables: N` во front-matter; pdfplumber/pypdfium2 объявлены прямыми
    зависимостями. +21 тест (всего 77). Проверено на реальном документе
    (Предзащита_ВКР_Липатова, 21 стр., 7 таблиц). Обзор — в
    `docs/pdf-tables-proposal.md`. Доработки по обратной связи:
    `_row_text` сохраняет переносы строк прозы (фикс «простыни» вокруг
    таблиц); конвертация псевдографики таблиц (`│┌┬┐…`) в GFM
    (`_convert_box_tables`/`_box_block_to_gfm` в `tidy`).
11. **Хардинг по внешнему аудиту (2026-06-27).** Закрыты low-находки:
    `_is_public_ip` явно отвергает CGNAT `100.64.0.0/10` (RFC 6598;
    `is_global` ошибочен на Python <3.13); `decode_html_bytes` ловит
    UTF-32 BOM до UTF-16 (иначе мусор); defensive-guard на пустой список
    в `_table_to_gfm`/`_join_continued_tables`. +тесты: subprocess
    TimeoutExpired→fail, редирект на приватный IP отвергается, CGNAT,
    UTF-32. 90 pytest-тестов. Принято как есть (не баги): DNS-rebinding
    TOCTOU URL (приемлемо для CLI с `--allow-private-url`), пин `magika`
    (см. выше), Windows-CI без ruff/lock-check (платформонезависимы —
    покрыты Linux-джобом).
12. **Фенсинг кода + отказ от text-стратегии таблиц (2026-06-27).** На
    корпусе из 10 реальных документов Astra (бюллетени/руководства):
    (а) убрана `text`-стратегия pdfplumber — она давала фейковые
    мега-«таблицы» и крошила SQL/код в огрызки (32 ложные таблицы на
    корпус, раскрошенный SQL в Ruk_KSZ_3 стр.8); настоящие таблицы целы;
    (б) добавлен построчный фенсинг кода/команд/конфигов в ```
    (`_classify_code_line`/`_fence_code_blocks`) — плейсхолдеры `<...>`,
    `#`-комменты, `|-vda` теперь рендерятся корректно. 0 ложных
    срабатываний на корпусе (3371 фенс). +10 тестов (всего 100).
13. **Триаж внешнего ревью + явный пин `requests` (2026-06-28).** Внешнее
    ревью оказалось в основном недостоверным: флагманская «критичная»
    находка (E501: «168 строк >79») сфабрикована — реально 0 строк >79,
    `ruff check (E/F/W)` чист. Остальные 281 — из правил, которые проект
    сознательно не включает (`--select ALL`), часть прямо вредна здесь
    (RUF002/003 на легитимной кириллице; T201 на `print` в CLI; «фикс»
    `[А-Яа-яЁё]` в латиницу сломал бы детектор). Проверены и отклонены как
    умышленный/корректный дизайн: `except Exception` вокруг сторонних
    парсеров недоверенного входа (фолбэк, чтобы один битый файл не ронял
    пакетный прогон); префиксное сравнение `_source_id_matches`
    (legacy-16↔new-32, backward-compat). Реализована единственная
    находка по делу: `requests` объявлен явной прямой зависимостью
    (`>=2.32,<3`) — он импортируется напрямую в `convert_url`, но шёл
    только транзитивно через `markitdown`. Изменение метаданных:
    резолв-версия (`requests 2.34.2`) и поведение не меняются. 107 тестов.
14. **Web-GUI + аудит и доработки (2026-06-28).** Локальный веб-GUI на
    FastAPI (`gui_server.py`, статика в `gui_static/`, опц. зависимость
    `[gui]`, команда `tomd-gui`): SSE-прогресс, превью (marked+DOMPurify),
    127.0.0.1 + проверка Host **и** Origin (CSRF), авто-выключение по
    heartbeat (graceful), LRU-хранилище скачиваний. По итогам внутреннего
    аудита (исполнение + сборка wheel + мульти-агентная перепроверка)
    закрыты: B1 (флаги через `Form`), B2 (скачивание из памяти),
    H1 (basename имени), S1 (Origin), упаковка `gui_static` в wheel,
    и **тихая порча при одинаковом stem в батче** — конвертация
    сериализована под `_CONVERT_LOCK` (убрана гонка глобального
    `redirect_stdout`/`opts["planned"]`), а точный путь вывода ядро кладёт
    в `opts["last_target"]` (без угадывания по stem). Добавлены сценарии
    «папка → .md на месте»: **①** правый клик по папке в Проводнике
    (`install.ps1`, `Directory[\Background]\shell` → `tomd -r`); **②**
    кнопки «Выбрать файлы/папку с диска» — родной диалог ОС (tkinter в
    subprocess; путь только из диалога, не из запроса) → `.md` рядом с
    исходником; **③** «Папка → ZIP» — `webkitdirectory` из браузера в
    один архив с сохранением структуры (zip-slip-safe). По обратной
    связи живого теста: превью выносит YAML-шапку в `<details>` (marked
    рендерил её гигантским setext-заголовком); строки результата —
    grid с фикс-колонкой кнопок (имя · кнопки · путь, не «едет»);
    загруженный `.zip` не склеивается MarkItDown в один `.md`, а
    разворачивается (`_convert_archive`) — каждый файл внутри → `.md`,
    отдаётся одним `.zip`; opt-in чекбокс «не проверять SSL» для URL
    (core `_download_url(verify_ssl=...)`, `opts["verify_ssl"]`,
    gui-флаг `insecure_ssl`). CI: отдельная `gui`-джоба
    (`--extra gui`). Тесты GUI — в `tests/test_gui.py` (127 всего).
15. **Архивы всех форматов + картинки из PDF + редизайн GUI
    (2026-06-29).** (а) **Архивы:** помимо `.zip` теперь `.7z` (py7zr,
    LGPL) и `.tar`/`.tar.gz`/`.tgz`/`.tar.bz2`/`.tbz2`/`.tar.xz`/`.txz`
    (`_archive_kind`/`_TAR_SUFFIXES`); RAR не берём (нужен проприетарный
    unrar). Потолок распакованного размера `_MAX_UNCOMPRESSED` 500 МБ
    (защита от 7z-OOM-бомбы); 7z — через `extractall` во временную папку
    и перекладка через `_safe_rel` (py7zr 1.x убрал `read()/readall()`).
    py7zr ≥1.1.3,<2 — в 0.22 три CVE. (б) **Картинки из PDF** при
    «Сохранять изображения»/`--keep-images`: `_pdf_images_markdown`
    (pypdfium2 → base64 по страницам, секции «Картинки страницы N»).
    Это в ядре `convert_file`, поэтому работает и в CLI, и в GUI;
    раньше PDF-картинки не доставались вовсе. (в) **Редизайн GUI** от
    дизайнера (бренд-стиль по иконке: градиент `#46E0A0→#2E2A6E`,
    карточки, drop-zone-арт, чекбоксы-пилюли) — взяли HTML/CSS дизайнера,
    но сохранили наш канонический инлайн-`<script>` (у дизайнера были
    неверные эндпоинты `/api/convert-url` вместо `/api/convert/url`);
    контракт в `docs/gui-contract.md` (16 id + обработчики + динамические
    классы). Фиксы интеграции: дефолты чекбоксов (дизайнер включил
    «Сохранять изображения» и выключил «Таблицы в PDF» — вернули эталон
    frontmatter+pdfTables вкл., остальные выкл.), точные подсказки
    `title`, имя класса drop-zone `.drag`→`.drag-over` (под канонический
    JS). Раскладка строк результата — «имя на всю ширину, кнопки/путь
    ниже» (длинное имя не режется). README и `docs/gui-guide.md`
    синхронизированы с новыми лейблами и фичами. 137 pytest-тестов.
16. **Фикс по аудиту: потоковый лимит распаковки архивов (2026-06-29).**
    Внешний аудит (вердикт GO-с-оговорками) нашёл один MEDIUM:
    заголовочная проверка 7z `if total and total > _MAX_UNCOMPRESSED`
    обходится при `uncompressed=0` (подделанный/пустой заголовок).
    Предложенный аудитором one-liner `if total > …` кейс НЕ закрывал бы
    (`0 > 500 МБ` тоже False). Реальный фикс: `_extract_archive._write`
    теперь считает фактические распакованные байты и обрывает запись на
    лету (`> _MAX_UNCOMPRESSED` → ValueError) — для zip/tar это потоковая
    защита от бомбы (раньше у них лимита не было вовсе), для 7z
    ограничивает перекладку из temp; заголовочная проверка осталась
    быстрым отказом на честных больших архивах. Остаточный риск: сам
    `extractall` 7z пишет подделанную бомбу в изолированный temp до
    счётчика (py7zr 1.x не стримит), temp чистится в `finally`. +тесты:
    zip сверх лимита, 7z с подделанным `uncompressed=0`, Origin: null →
    403 (аудитор отметил как непокрытый). Находка аудитора «PDF-картинки
    без тестов» — ложная: `test_pdf_images_extracted`/`_empty_on_missing`
    уже есть. End-to-end тест: zip-бомба сверх лимита → чистое
    error-событие (status 200, _convert_archive ловит ValueError, без
    500/обрыва стрима). 141 pytest-тест.

17. **Хардинг GUI по итогам ревью + верификации (2026-08-03).** Внешнее
    ревью проверено адверсариально (10 агентов, эмпирические тесты):
    факты в основном верны, но калибровка слабая — 2 рекомендации из
    ~20 при исполнении внесли бы регрессию (снятие `_CONVERT_LOCK`:
    он держит ГЛОБАЛЬНЫЙ `redirect_stdout` и `opts["planned"]`, а не
    только `last_target`; удаление `max_url_mb`: ключ живой, его
    читает `_build_opts`). Обе отклонены; НЕ «чинить» повторно. Зато
    ревью пропустило то, что нашла перепроверка, и это исправлено:
    (а) `ValueError` из `_gui_opts` (запретная «Папка вывода», кривой
    `only`) летел мимо SSE-генератора → голый **500** на всех четырёх
    эндпоинтах; теперь `_bad_request` → 400 с причиной, фронтенд
    показывает её при `!resp.ok`; (б) **тихая потеря данных**: два
    одноимённых файла в батче писались в один `tmpdir/<имя>`, второй
    затирал первый ДО конвертации → в выдаче дважды контент второго;
    теперь у каждой загрузки своя подпапка `tmpdir/<idx>/`; (в) в
    `/api/convert/zip` не применялись собственные лимиты
    `_MAX_ARCHIVE_FILES/_BYTES`, плюс при пустом/битом JSON `paths`
    одноимённые файлы снова затирали друг друга — лимиты применены,
    развод имён через `_unique_path` ТОЛЬКО при реальной коллизии (в
    ③ структура подпапок — сам результат, безусловный префикс её
    сломал бы); текст предупреждения написан заново, а НЕ скопирован
    из `_convert_archive`: там отсечённый файл остаётся скачиваемым и
    есть запасной путь `out_dir`, здесь `download_id` пуст и
    `out_dir` всегда `None`, поэтому сообщение перечисляет
    потерянные имена; (г) `_ZIP_STORE` имел лимит только по числу
    записей (5) — добавлены `_MAX_ZIP_BYTES` 200 МБ и `_ZIP_TTL`
    30 мин; (д) размер везде считается в **БАЙТАХ utf-8**
    (`_utf8_len`): на кириллице байт вдвое больше, чем символов, и
    посимвольный счёт пропускал бы ~2x лимита в ОЗУ (находка codex);
    (е) `_, _, _ = _downloads.popitem(...)` — `popitem` отдаёт ПАРУ,
    распаковка в три цели роняла `ValueError` в SSE-генераторе, как
    только сумма скачиваний превышала 50 МБ; (ж) копия `.md` из
    архива в `out_dir` затирала существующий файл вопреки
    `[skip]`-семантике ядра — теперь запись АТОМАРНА (`open("x")` без
    force; `exists()`+`write_text` — гонка, `_CONVERT_LOCK` держит
    только конвертацию, не копирование), при конфликте `skip` +
    новое поле SSE `note`; (з) `asyncio.create_task` в `_lifespan`
    без сохранения ссылки (event loop держит слабую) — задачи ведёт
    `_spawn_background`. Доки приведены к коду: архив
    разворачивается, только если подан САМ (при обходе папки, в т.ч.
    CLI `tomd -r`, архивы внутри пропускаются); порог чистки
    колонтитулов — `max(5, page_count // 2)`, т.е. на 3-4 страницах
    колонтитул остаётся (проверено эмпирически). Каждый новый тест
    проверен на ОТКАТЕ фикса — так поймано два собственных пустых
    теста (проходили и со сломанным кодом).
    **Пост-проверка (8 независимых агентов) нашла ещё три вещи, они
    тоже исправлены:** (и) в «Папка → ZIP» архив НЕ пропускался, а
    уходил в MarkItDown и давал пустую заглушку `.md` с временным
    путём сервера внутри — содержимое терялось молча; теперь
    пропускается с видимой ошибкой (и документация про обход папки
    стала правдой); (к) регрессия от (ж): `FileExistsError` от
    `mkdir` (компонент пути занят файлом) попадал в обработчик skip и
    врал «`.md` уже есть» даже при включённой перезаписи — mkdir
    вынесен в отдельный try; (л) строка-пояснение в карточке была
    однострочной с ellipsis, поэтому перечень не вошедших в архив
    файлов физически не читался — включён перенос. Плюс закрыт
    красный CI: тесты 400 подавали `C:\Windows`, что на
    ubuntu-раннере не системная папка (заменено на UNC-путь,
    windows-ветка вынесена под `skipif`), и обновлены `pillow`
    12.3.0 / `cryptography` 50.0.0 — 21 CVE от pip-audit.
    Итого 160 pytest-тестов (+19).

    сохраняет, и ремонт отрабатывает (тест
    `test_repair_alternate_font_footnote_lines` подаёт именно
    pypdfium2-форму и даёт «При оценке»). Вывод для будущего: это
    ограничение ИЗВЛЕКАТЕЛЯ, а не ремонта. **(б) Реальный дефект:
    словарь строился только по сырому
    тексту.** Прогон без единой уцелевшей русской буквы переводится
    лишь при подтверждении словарём, но слова, которые в документе
    встречаются ТОЛЬКО сломанными, в сыром словаре отсутствуют по
    определению. Теперь ремонт делает два прохода: словарь второго
    собирается по результату первого (1001 → 2213 слов на реальном
    документе), перевод всегда заново из ОРИГИНАЛА. Последнее —
    защитный инвариант (карта заведомо не применяется дважды), а НЕ
    оптимизация: замерено, что цепочка «второй проход по результату
    первого» даёт на реальном документе идентичный вывод (0 различий).
    Не переписывать на цепочку: инвариант дешёвый, а гарантия его
    ценнее. **Почему именно два прохода:** замерено, что словарь
    насыщается за один раунд (1001 → 2219, следующий раунд +0), и
    третий проход даёт побайтово тот же вывод — два прохода это
    неподвижная точка, а не произвольное число. Не превращать в
    неограниченный цикл: каждый лишний раунд только расширяет шлюз и
    добавляет риск петли обратной связи (ошибочный ремонт → ошибочное
    слово в словаре → новые ошибочные ремонты). Проверено также
    `repair(repair(x)) == repair(x)`. Замер на реальном документе:
    второй проход принимает РОВНО два прогона, оба верных
    (`<>4C;59` → «модулей»,

    полный диff вывода — те же две строки, 0 регрессий. Отвергнуто:

    словарь берёт ТОЧНЫМ совпадением, то есть безопаснее; (2)

20. **Заглавные второго шрифта, спрятанные в пунктуации
    (2026-08-29).** Широкий аудит выхода (не только на кириллицу, но
    и на таблицы, фенсы, заголовки, переносы) нашёл то, что три
    прошлых прохода пропустили: 7 строк РУССКОЙ ПРОЗЫ внутри
    код-фенсов. Оказалось, это не ошибка фенсинга, а его СЛЕДСТВИЕ —
    прозу зафенсило потому, что она осталась недоремонтированной и
    полна пунктуации (`Г !"`, `Ф!"ЭК оссии`, `« азработка`).
    **Причина.** У второго шрифта прописные Р..Я лежат не в
    управляющих, а в ПЕЧАТНЫХ `0x20..0x2F` со смещением B0: «Р» — это
    пробел, «С» — `!`, «Т» — `"`, «Я» — `/`. Слепой перевод погубил бы
    все настоящие пробелы, а «С/С++» превратил бы в «СЯСЫЫ», поэтому
    их не трогали вовсе. **Решение — тот же принцип улики, что и в
    пункте 19, но арбитр другой: частота.** Для слова: пробел перед
    ним был буквой, если слово С заглавной встречается в документе
    ЧАЩЕ, чем без неё («азработка» 1 против «разработка» 4, «оссии» 1
    против «россии» 15). Обычное слово после настоящего пробела так не
    проходит: «Рбезопасного» в документе 0 раз. Для аббревиатуры
    арбитр прежний, словарный: `Ф!"ЭК` → «ФСТЭК», потому что «ФСТЭК»
    в документе есть целым. Из карты исключены «ъ», «ы», «ь» (русское
    слово с них не начинается), заодно из набора уходят частые `*`,
    `+`, `,`. Правило применяется ТОЛЬКО к строкам второго шрифта (8
    из 2197). **Тонкость, которую нельзя упрощать:** пробел-буква
    поглощает и разделитель слов, поэтому после буквы/цифры
    разделитель возвращается («ФСТЭК России»), а после кавычки — нет
    (««Разработка»). Обе ветки закреплены тестом. Замер на реальном
    документе: принято 3 восстановления (2 слова + 1 аббревиатура),
    все верные, ложных 0; полный диff итогового `.md` — ровно 2
    строки. Граница закреплена тестом
    `test_repair_keeps_real_punctuation_in_alt_font`, проверенным
    красным при снятии обоих шлюзов. **Остаток и его точная
    причина.** `Г !"` («ГОСТ Р») не чинится не из-за правила, а
    потому что `pdfplumber.extract_text()` сплющивает `\x1e` (это «О»)
    в пробел — без «О» аббревиатура словарём не подтверждается.
    Замерено: на тексте pypdfium2, где `\x1e` сохраняется, ТО ЖЕ
    правило даёт «ГОСТ». Смена извлекателя отвергнута сознательно:
    ради одного вхождения она затронула бы таблицы, порядок чтения,
    чистку колонтитулов и фенсинг разом. По той же причине остаются
    „ри“/„од“ вместо «При»/«Под»: pdfplumber отбрасывает ведущий
    `\x1f` («П») вместе с номером сноски, декодировать нечего

    слишком широкая формулировка про управляющие символы).
    Также осознанно не чинятся
    однобуквенные слова (`4 также` → «а также», `6 предыдущих` → «в

26. **Ревизия качества конвертации + фиксы по её итогам (2026-08-29).**
    По жалобе «после того PDF всё поползло» — ревизия 4 параллельными
    аудиторами: документ ФСТЭК против эталонных метрик, 3 других
    реальных PDF, 9 форматов с таблицами, полный CI-набор. Подозрение
    НЕ подтвердилось: ФСТЭК совпал с эталоном метрика в метрику
    (13160 слов, 40 таблиц, 74 фенса, все принятые остатки на месте,
    не размножились). Но ширина нашла три настоящих дефекта, все
    исправлены (каждый тест наблюдался красным):

    порча hex-констант («345»→«где», «ISO/IEC»→«ихяы/хсп»): гейт
    поднят с 1% до 3% плотности + чисто цифровые прогоны не
    переводятся (см. known-limitations);

    бывает смещён ((-0.05, -0.2, 594.95, 841.8)), crop от

    подстановок τ/π′, формулы). `_crop_text` клампит координаты к
    реальному bbox; ГОСТ вернул +223 слова;
    (в) **фолбэк MarkItDown без чистки колонтитулов**: Р 71207-2024
