# CLAUDE.md — онбординг для AI-агентов

**md-converters** — конвертация документов в Markdown на базе
[MarkItDown](https://github.com/microsoft/markitdown): PDF, HTML, Word,
Excel, PowerPoint, CSV, JSON, XML, EPUB, Outlook `.msg`, Jupyter,
архивы, веб-страницы по URL. Команда `tomd` + Web-GUI (`tomd-gui`).
Язык проекта — русский: интерфейс, README, комментарии, коммиты.
Пользователь: Виталий Пиков (vitaliy@pikov.com), DevSecOps; конвертирует
отчёты (SBOM, уязвимости, ГОСТ/РБПО) в базу знаний.

## Принципы (по Карпаты; выстраданы практикой проекта)

1. **Думай до кода.** Допущения называй явно; несколько трактовок —
   покажи, не выбирай молча; видишь путь проще — скажи и обоснуй.
2. **Минимализм.** Ровно тот код, что решает задачу. Без запаса «на
   будущее», без абстракций для одноразового, без непрошеной
   конфигурируемости. 200 строк, которые могли быть 50, — переписать.
3. **Хирургия.** Трогай только необходимое. Соседний код, комментарии
   и форматирование не «улучшай»; стиль — как вокруг. Каждая
   изменённая строка прослеживается к запросу пользователя.
4. **Цель — проверяемый критерий.** Фикс = красный тест, который
   зеленеет. Железные правила проекта: (а) новый тест проверяется НА
   ОТКАТЕ фикса — обязан краснеть (так поймано несколько пустых
   тестов); (б) эвристика, замеренная на одном документе, — гипотеза,
   а не результат; (в) видимо сломанный токен честнее невидимой порчи.

## Факты

- Канон: `V:\md-converters`, единственная ветка `main`, репо публичный
  (Actions бесплатны). Git-операции: `git -C "V:\md-converters" ...`.
- `convert_to_md.py` — ВСЁ ядро и CLI (`tomd`/`pdf2md`/`html2md` —
  console_scripts `cli_tomd`/`cli_pdf`/`cli_html`). `gui_server.py` +
  `gui_static/` — Web-GUI, слой ПОВЕРХ ядра (экстра `[gui]`); контракт
  фронтенда — `docs/gui-contract.md`, менять разметку без сверки нельзя.
- Строки `.py` ≤ 79 символов (ruff E501). Комментарии — про «почему».
- Проверки перед коммитом (тот же набор, что CI):
  `uv lock --check && uv run --frozen --extra gui ruff check
  convert_to_md.py gui_server.py tests tools && uv run --frozen
  --extra gui pytest -q`.
- Команды `tomd`/`pdf2md`/`html2md`/`tomd-gui` (PATH), функции
  профиля PowerShell и `.venv` — ВСЕ исполняют живой код репозитория
  (2026-08-29 оба системных Python переведены на `pip install -e`).
  На новом ПК редактируемую установку повторить: install.ps1 ставит
  зависимости, но не пакет (docs/known-limitations.md, «Окружение»).
- Коммиты на русском; последняя строка — соавтор с именем ТЕКУЩЕЙ
  модели: `Co-Authored-By: Claude <модель> <noreply@anthropic.com>`.
  Push в `main` разрешён; в конце правок `git status -sb` должен
  показывать `## main...origin/main` без расхождений.

## Не чинить заново (проверено и отклонено)

- `_CONVERT_LOCK` в GUI и контракт `convert_file() -> str`: лок держит
  ПРОЦЕСС-ГЛОБАЛЬНЫЙ `redirect_stdout` и общий `opts["planned"]`.
- Ключ `max_url_mb`: живой, его читает `_build_opts` → `KeyError`.
- `except Exception` вокруг сторонних парсеров: фолбэк, чтобы один
  битый файл не ронял пакетный прогон.
- Префиксное сравнение `_source_id_matches`: legacy-совместимость.
- Кириллические регексы детектора прозы; `print` в CLI.
- Обоснования и полный разбор: docs/known-limitations.md и
  docs/history.md (п. 13, 17).

## Подводные камни

- Кириллица в имени `.lnk`: создавать с латинским именем, затем
  `Rename-Item` (WScript downconvert'ит в ANSI).
- `.ps1` — профиль писать с `utf8BOM` (читают и PS 5.1, и 7).
- Песочница блокирует `Remove-Item` с маской `\*` — используй
  `-LiteralPath` на конкретную папку.
- Работающий `tomd-gui` держит код в памяти: после правок сервер
  перезапустить, иначе браузер получает старьё.
